# Java内存模型

volatile关键字：易变的，也就是告诉系统该变量可能会被多线程修改，一定要从内存读写（不使用缓存）



```java
class VolatileExample {
  int x = 0;
  volatile boolean v = false;
  public void writer() {
    x = 42;
    v = true;
  }
  public void reader() {
    if (v == true) {
      // 这里x会是多少呢？
      读变量x;
    }
  }
}
```

对于1.5版本之前的Java，x可能会是0或42，原因是缓存（v虽然是volatile，x可不是哦）

对于1.5版本之后的Java，x只会是42（happens-before原则发力了）







Java内存模型在1.5对volatile语义进行了增强，具体来说是遵循了**Happens-Before规则**

该规则的含义是：**前面一个操作的结果对后续操作是可见的**





**1.程序的顺序性规则**

程序中前面的操作 happens before后面的操作

**2.volatile变量规则**

一个volatile变量的写操作， Happens-Before 于后续对这个volatile变量的读操作

**3.传递性**

A Happens-Before B，且B Happens-Before C，那么A Happens-Before C

这条是关键，上面的例子中1.5之后不会出现v=0就是因为:

- `x = 42` happens before `v = true`
- `v = true` happens before `读变量x`

则有`x=42` happens before `读变量x`，因此1.5之后只会读到x为42，这就解决了可见性的问题





4.管程中锁的规则

Java中的管程就是关键字`synchronized`，解锁happens before于加锁



5.线程start()规则

指主线程A启动子线程B后，子线程B能够看到主线程在启动子线程B前的操作。



6.线程join原则

指主线程A等待子线程B完成（主线程A通过调用子线程B的join()方法实现），当子线程B完成后（主线程A中join()方法返回），主线程能够看到子线程的操作。当然所谓的“看到”，指的是对**共享变量**的操作。
