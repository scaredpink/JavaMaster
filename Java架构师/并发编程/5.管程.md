# 管程

管程（Monitors），是一种程序结构，用来实现<u>多个线程互斥地访问共享资源</u>（一般是硬件或者变量）。

管程实现了<u>在一个时间点，最多只有一个线程在执行管程的某个子程序</u>。

管程实现了同步机制，线程可以临时放弃互斥访问，等待某些条件得到满足后，重新获得执行权恢复它的互斥访问。



管程与信号量等价。



Java 1.5 之前提供的`synchronized`、`wait()`、`notify()/notifyAll()`实际上就是按照管程的概念提供的并发原语。其中`synchronized`就是管程中的条件变量，只不过其只支持单一条件变量。后续`J.U.C`包的出现才支持了多个条件变量。





## 管程模型

<img src="https://static001.geekbang.org/resource/image/83/65/839377608f47e7b3b9c79b8fad144065.png" alt="img" style="zoom:48%;" />

共享变量：指的就是管程中那个需要互斥访问的资源；

条件变量：指的是线程在执行前需要满足的条件，用来实现同步机制；

入口等待队列：可以理解为试图访问共享变量的线程们，需要排队等待；

条件变量等待队列：指的是线程在执行前需要满足的条件，如果条件不满足，就会排到条件变量等待队列；等到条件满足，线程就会重新回到入口等待队列里排队等待。



## 现实例子

现实中可以以医院看病的过程来对应一个管程模型：

线程：病人

共享变量：医生

条件变量：看病的依据（例如验血报告，X光片等）
