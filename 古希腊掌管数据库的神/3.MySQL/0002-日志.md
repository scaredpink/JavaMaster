# 日志

> ​	数据库可以恢复到半个月内任意一秒的状态。



​	MySQL的日志包含**通用查询日志**、**慢查询日志**、**错误日志**、**二进制日志**、**中继日志**、**重做日志**和**回滚日志**。

​	日志的作用包括数据复制、数据恢复、操作审计，以及确保数据的永久性和一致性等方面，对于使用者非常重要。

## redolog



WAL（Write-Ahead Logging）







数据库本身也是在服务器上运行的，自然也会有内存和磁盘。

redo log就是在内存改了以后记录在案，暂时不着急同步到外存上，等到服务器空闲的时候再同步到磁盘上

数据页在内存失效的时候，更新是一定会同步回磁盘上的。

如果数据页尚未更新到磁盘时服务器重启，内存全清，这时候由于有redo log在，启动后可以按照redo log把更新补回来，不用担心



binlog和redo log都能恢复数据，应该用哪个呢
