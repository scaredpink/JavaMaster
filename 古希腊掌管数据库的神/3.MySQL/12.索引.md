# 索引

索引是帮助MySQL系统快速检索数据的一种存储结构

## 一、单字段索引

### 1.创建索引

创建索引的方式有三种：

1.CREATE语句给已经存在的表创建索引:

```sql
CREATE INDEX 索引名 ON TABLE 表名 (字段);
```

2.创建表的时候同时创建索引:

```sql
CREATE TABLE 表名
(
		字段 数据类型,
		….
{ INDEX | KEY } 索引名(字段)
)
```

3.ALTER改表创建索引

```sql
ALTER TABLE 表名 ADD { INDEX | KEY } 索引名 (字段);
```



主键和唯一键会在创建时会自动创建索引。

### 3.索引字段选择

一般来说，查询条件是什么我们就会用那个字段作为索引

但是，很显然如果一个筛选条件在筛选后剩余的行数更少，那么它作为索引的区分度就越好，查询的时间也就越短

因此我们最好使用区分度更高的字段作为索引

```sql
SHOW INDEX FROM 表名
```

可以通过cardinality来看索引唯一值基数，如果基数越大，说明区分度越高，索引效果越好





## 二、组合索引

顾名思义，组合索引就是对应多个表字段的索引，针对筛选条件包含多个字段的情况。

MySQL最多支持16个字段组成的组合索引。

### 1.创建组合索引

1.CREATE语句给已经存在的表创建索引:

```sql
CREATE INDEX 索引名 ON TABLE 表名 (字段1, 字段2);
```

2.创建表的时候同时创建索引:

```sql
CREATE TABLE 表名
(
		字段 数据类型,
		….
{ INDEX | KEY } 索引名(字段1, 字段2)
)
```

3.ALTER改表创建索引

```sql
ALTER TABLE 表名 ADD { INDEX | KEY } 索引名 (字段1, 字段2);
```





### 2.组合索引的原理

组合索引遵循左对齐原理，即从左往右开始，如果中间有筛选条件断掉，断点后的条件就没有办法利用索引了。

如果组合索引不能完全使用，可能还不如使用单索引



最后，我来跟你说说索引的成本。索引能够提升查询的效率，但是建索引也是有成本的，主要有2个方面，一个存储空间的开销，还有一个是数据操作上的开销。

- 存储空间的开销，是指索引需要单独占用存储空间。
- 数据操作上的开销，是指一旦数据表有变动，无论是插入一条新数据，还是删除一条旧的数据，甚至是修改数据，如果涉及索引字段，都需要对索引本身进行修改，以确保索引能够指向正确的记录。

因此，索引也不是越多越好，创建索引有存储开销和操作开销，需要综合考虑。
